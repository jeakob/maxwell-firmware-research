# v1.0.1.38 — the launch-era firmware, and what changed after it

Some owners remember `v1.0.1.38` as the best-sounding Maxwell firmware, with
the best sidetone. This page records what is known about it as of October
2026. It covers whether the image can be obtained, what Audeze changed between
v38 and v74, and what the binaries we *do* have show.

## Can v38 be obtained?

**No public copy has been found.**

- The [maxwell-balance-and-firmware-tool](https://github.com/kats1123/maxwell-balance-and-firmware-tool)
  bundles only `v1.0.1.56`, `v61`, `v63` and `v74` (Xbox and PS, headset and
  dongle). Nothing older is in its `firmware/` folder, its embedded `src/stock_*.bin`
  images, or its git history. None of its issues ask for older versions.
- Audeze does not publish firmware files directly. Updates come through
  Audeze HQ, and v61 removed the rollback feature from HQ.
- Web searches for the filename or version found no mirror of the image.

The most likely place for a copy to survive is an old Audeze HQ install or
download cache from around March–May 2023, before v46 replaced it. This is
**unverified**; we do not know whether HQ caches firmware locally. If anyone
has the `.bin` files, the tools in this repo can decompress and diff them like
any other version.

### Risks of flashing v38 even if found

- **Dongle/headset mismatch.** v51 required re-pairing the dongle after the
  update. That points to a pairing or protocol change, so a v38 headset with
  a v56+ dongle may not pair. The tool already warns that v56 pairs
  unreliably with a newer dongle. The dongle would have to be on v38 too, and
  no v38 dongle image is known to exist either.
- **Pairing procedure.** Audeze's support article says firmware ≤ v1.0.1.46
  needs the noise-reduction button held while triple-tapping power to enter
  pairing mode.
- **Untested FOTA path.** The flashing recipe in [FLASHING.md](FLASHING.md)
  has only been confirmed on v56–v74.
- **Known v38-era bugs** (fixed in v46/v51): mic dropouts after BT calls,
  muted-mic leakage, BT disconnects on the dongle, and volume-sync problems.

## What Audeze changed after v38 that affects sound or sidetone

From Audeze's official [change log](https://www.audeze.com/pages/maxwell-patch-notes)
(paraphrased):

| Version | Date | Sound / sidetone / gain changes |
|---------|------|-------------------------------|
| **v1.0.1.38** | 2023-03-16 | Game/Chat balance synced between USB and ULL modes; **PS digital-to-analog gain matched to PC** (0 dBFS 1 kHz → 105 dB SPL). |
| v1.0.1.46 | 2023-05-15 | **Amplifier gain increased.** **Sidetone behaviour changed "to improve battery performance."** Mic settings adjusted for battery life. Known issue added: "low-level noise with sidetone enabled." |
| v1.0.1.51 | 2023-08-29 | **"Improved noise levels in some sidetone scenarios."** **Boom-mic analog gain reduced.** EQ/LDAC glitch fixes. Needed a dongle re-pair. |
| v1.0.1.56 | 2024-01-23 | Xbox sidetone level **converted to a percentage**, with a real-time UI. Fixes for a wrong sidetone level after re-linking, and for the sidetone on/off command during streaming. |
| v1.0.1.61 | 2024-04-29 | "Fixed tuning inaccuracies with some EQ presets." Per-source balance system added (see [README.md](README.md)). |
| v1.0.1.63 | 2024-06-07 | Fixed artifacts when playback stops. |
| v1.0.1.74 | 2024-09-27 | **Volume limiter** made more stable. **Output gain "slightly adjusted."** EQ fix for upgrades from older firmware. |

Audeze support has also said that sidetone gain was raised after complaints
that it was too quiet. That caused more feedback, so a later update lowered it
slightly. Audeze does not say which versions those were.

### Reading the log against "v38 sounded better"

- **Sidetone.** The sidetone path was reworked in v46 (power saving), v51
  (noise reduction) and v56 (percentage scaling on Xbox), and Audeze retuned
  its gain at least twice. Of every release after v38, these are the changes
  most likely to explain a different sidetone character. The noise reduction
  in particular may involve gating or filtering that changes how natural the
  sidetone sounds.
- **Mic level.** v51 reduced the boom-mic analog gain. Sidetone is your own
  mic fed back to you, so this also changes how loud and present the sidetone
  is.
- **Overall sound.** v46 raised the amplifier gain, v61 retuned EQ presets,
  v74 adjusted output gain and the limiter, and v61 added the per-source L/R
  balance bug. Any of these can make v74 sound different from v38 with the
  same settings in the app.

## What the binaries we have show (v56 → v74)

Run with [`tools/compare_nvdm_keys.py`](tools/compare_nvdm_keys.py) on the
Xbox and PS headset images:

| NVDM key | Meaning | v56 | v61 | v63 | v74 |
|----------|---------|-----|-----|-----|-----|
| `0xF66E` | sidetone-related factory default | `0x0901` | `0x0901` | `0x0901` | `0x0901` |
| `0xF668` | wireless L/R balance | `142/142` | `141/141` | `141/141` | `147/147` |
| `0xF665` | USB-C L/R balance | — | `141/149` | `141/149` | `141/149` |

- The sidetone-related NVDM default does not change between v56 and v74. So
  any sidetone difference *within* that range is not in the factory NVDM
  defaults. It would be in DSP code or coefficient tables, which have not
  been mapped yet. All the logged sidetone rework (v46, v51, v56) falls in
  the v38→v56 gap, which we have no binaries for.
- The binaries show `0xF668 = 141/141` in v61/v63, as
  [VERSIONS.md](VERSIONS.md) says. [README.md](README.md) and the tool README
  say `147/147` for v61; the binaries do not support that (see the tool's
  issue #2).

## Practical options today

1. **v1.0.1.56** is the oldest firmware that can actually be flashed. It
   comes after all the logged sidetone rework, but before the v61 EQ retune,
   the per-source balance bug and the v74 gain/limiter change. If v74 is the
   problem, try v56 first. Flash the dongle first, then the headset.
2. **Custom v74/v56 via the tool** fixes L/R balance and forces the
   symmetric wireless profile. It does not change sidetone.
3. **Sidetone on v74.** The RACE `0x2C00` range handles chatmix/sidetone
   (see [PROTOCOL.md](PROTOCOL.md)). The sidetone level is in the audio
   state struct at `+0x2C..0x30` (see [AUDIO.md](AUDIO.md)). Mapping those
   fields is the next step towards a sidetone patch.
4. **If a v38 image turns up**, decompress it and diff it against v56 with
   `compare_versions.py` and `compare_nvdm_keys.py`. Focus on `0xF66E` and
   the `0x2C00` handler.
